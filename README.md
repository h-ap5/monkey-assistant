# 몽키 어시스턴트

Tampermonkey 백업 ZIP과 `.user.js` 파일을 브라우저 안에서 분석해 다음 항목을 정리하는 정적 웹앱입니다.

- 스크립트 이름·버전·작동 사이트·기능 요약
- 완전히 같은 코드 복사본
- 같은 계열의 여러 버전
- 공통 선택자·저장 키·통신 후킹 기반 기능 중복 및 충돌 후보
- 로컬 상담 어시스턴트
- 고양이체·간신체·군대체·메이드체·커스텀 말투
- HTML 분석 보고서 저장

외부 API를 사용하지 않으며, 선택한 파일은 서버로 업로드되지 않습니다. 데이터는 현재 브라우저의 IndexedDB에만 저장됩니다.

## 로컬 실행

`index.html`을 직접 열어도 대부분 작동하지만, 브라우저의 로컬 파일 보안 정책에 따라 저장 기능이 제한될 수 있습니다. 간단한 로컬 서버 실행을 권장합니다.

```bash
python -m http.server 8080
```

그 뒤 `http://localhost:8080`에 접속합니다.

## GitHub Pages 배포

### 가장 쉬운 방법: 브랜치에서 배포

1. GitHub에서 새 저장소를 만듭니다.
2. 이 폴더 안의 파일을 저장소 최상단에 모두 업로드합니다.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment**에서 `Deploy from a branch`를 선택합니다.
5. Branch를 `main`, 폴더를 `/(root)`로 선택하고 저장합니다.
6. 잠시 뒤 아래 형식의 주소가 생성됩니다.

```text
https://깃허브아이디.github.io/저장소이름/
```

### GitHub Actions로 배포

이 프로젝트에는 `.github/workflows/pages.yml`도 포함되어 있습니다. 저장소의 Pages Source를 **GitHub Actions**로 선택하면 `main` 브랜치에 올릴 때 자동 배포됩니다.

## Tampermonkey 백업 사용법

Tampermonkey 관리 화면에서 **유틸리티 → ZIP → 내보내기**로 백업 파일을 만든 뒤, 웹사이트의 업로드 박스에 ZIP 그대로 넣습니다. 압축을 풀 필요가 없습니다.

## 참고

기능 중복과 충돌 판정은 정적 코드 분석 기반의 후보 표시입니다. 완전 중복은 코드 해시로 판단하지만, 기능 중복·충돌은 실제 실행 환경에 따라 다를 수 있습니다.
